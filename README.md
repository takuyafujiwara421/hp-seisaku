| | 内容 |

## ★設計の方針

**共通CSSを持たない。** 4つとも独立したスタイルを内包している。
共通CSSで色だけ変えると「結局テンプレート」に見えてしまい、
業種ごとに設計を変えているという最大の売りが伝わらなくなるため（実際に一度そうなって作り直した）。

- 工務店 … 写真が主役。施工事例に坪数・工期・価格まで載せる
- 士業 … 写真では選ばれない。実績の数字・在留資格の一覧・不許可理由の解説で専門性を見せる
- 町中華 … 来店前に知りたいこと（営業時間・場所・値段）を最短で。写真が無くても成立させる

## ★踏んだ罠（次に触るとき必ず読む）

- **Chrome headless は `--window-size=390` を指定しても実際は500px幅で描画**して切り取るだけ。
  スマホ表示の検証は「**390pxのiframeに入れて `scrollWidth==clientWidth` を測る**」こと
- **CSSの詳細度**：`.nav a`(0,1,1) は `.btn`(0,1,0) に勝つ。ヘッダー内のボタンが
  濃い背景に暗い文字になって読めなくなる
- **`position:absolute; top:0` のヘッダー**は、上に別の帯（デモ注記など）があると裏に潜る。
  基準となる親に `position:relative` を置く
- **多言語サイトはフォント指定順が効く**。日本語フォントを先頭に書くと、
  ベトナム語の声調記号（về/miễn/lần）を描けず記号が分離する。
  **「ラテン系 → 日本語 → sans-serif」の順**にすること
- **円の中に文字を置くとき**、`line-height` での中央寄せは border 分ずれる。
  文字を `span` で包んで flex/grid の中央寄せにする
- 生成した文章に**外国語が紛れ込むこと**がある（実際に「예산」「three代目」「single品」が混入した）。
  公開前に必ず `grep -E '[А-Яа-я]|[가-힣]'` で検査する

## 内装カットの追加手順

```bash
cd ~/projects/hp-seisaku
./next-prompt.sh      # プロンプトが1つクリップボードに入る（4回繰り返す）
                      # → Geminiで新しいチャットを開き cmd+v → Enter → 画像を~/Downloadsへ
./add-images.sh 04-doma 05-laundry 06-nook 07-workspace   # リサイズ・圧縮して取り込み
```

★**画像の取り出しは自動化できない**（2026-08-14に確認）。
Geminiでの生成までは拡張から操作できるが、取り出し口が全部塞がっている:

| 手段 | 結果 |
|---|---|
| ダウンロードボタンをクリック | 押せるがダウンロードが発火しない |
| 「画像をコピー」ボタン | クリップボードに画像が入らない |
| `fetch(blob:...)` | CORSで失敗 |
| canvas → base64 で取り出す | ツール側が Base64 データの返却をブロック |

→ **ダウンロードだけは手でやる**のが結局いちばん早い。
